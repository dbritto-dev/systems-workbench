Systems lesson 35 · BM25

BM25 Workbench

BM25 is the ranking behind most keyword search: it adds up, for every query word a document contains, how rare the word is, how often the document uses it (with diminishing returns) and how long the document is. It's fast, needs no training and is unbeatable on exact codes and names, but it only matches words, not meaning. This lesson weighs documents on an assay bench: watch a machine do it, predict what changes the ranking, then explain it back.

01

The machine

The query's words stand on the rack as weights: a word found in few documents is a big weight, a word found everywhere a sliver. The assayer places them one at a time, and each of the five best documents gets a disc in its pan for every query word it contains. The disc's thickness is what that word adds to the score, so the stack is the score. Try the queries, k1 (how much repeats count) and b (how much length counts), and stuff a keyword into D16.

02

Predict, then run

Each experiment changes one thing. Choose what you expect before running it. Results come from the same BM25 code as the machine, on the same 36 documents.

1. A common word against a rare one

Experiment 1 of 5
Query “the printer” · D35, the office guide, says “the” 17 times and never “printer” · D06, a printer checklist, says “printer” once
Which of the two ranks higher?

IDF is about how many documents a term appears in. “the” is in all 36, so its IDF is 0.01; “printer” is in 5, so its IDF is 1.91, about 140 times heavier. Repeating a feather 17 times still gives a feather. On the bench, “the” is a weight you can barely see, and D35's pan gets a disc too thin to read.

2. Keyword stuffing

Experiment 2 of 5
D16 (“Cheap flights to Lisbon …”) repeats “cheap” 20 times instead of once · query “cheap flights” · k1 = 1.2, b = 0.75
How much bigger does the “cheap” part of D16's score get?

BM25 bends term frequency toward a ceiling of IDF × (k1 + 1): with k1 = 1.2 the “cheap” part goes 3.59 → 5.74 at 5 repeats → 6.47 at 20, against a ceiling of 7.05. Each repeat also makes D16 longer, which costs it a little more. k1 = 0 ignores repeats entirely (only presence counts); k1 = 3 lets them count for longer (10.46 at 20). Raw term frequency, as in plain TF-IDF, would have gone up 20×.

3. A short and a long document

Experiment 3 of 5
Query “kernel panic” · D03 (14 words) and D36 (63 words) each say “kernel” once and “panic” once · the average document is 20.3 words · b = 0.75
How do their scores compare?

A match in a short document says more about what the document is about than the same match lost in a long one. b decides how much length counts: with b = 0 both score 3.81; with b = 0.75 D03 scores 4.37 and D36 2.05; with b = 1 the gap grows to 2.6×. On the bench, look at the LEN gauges: the needle stands at the middle for an average length.

4. An error code, and the same problem in other words

Experiment 4 of 5
D08 is the article about ERR_CONNECTION_RESET · query 1: “ERR_CONNECTION_RESET” · query 2: “browser keeps dropping the link to the website”
Where does D08 rank for each query?

The code is one rare token that appears in exactly one document, so D08 scores 3.59 and everything else 0: exact identifiers, product numbers and error strings are what BM25 is best at. The description shares no word with D08 except “the”, so D08 scores 0.02 and the top result is D09, which matched “website”. BM25 matches words, not meaning: that vocabulary gap is what semantic search (lesson 36) closes, and why hybrid search (lesson 38) runs both.

5. Adding “the” to the query

Experiment 5 of 5
Query “kernel panic” → “the kernel panic” · no stop-word list
What happens to the top five?

BM25 needs no stop-word list for this: “the” is in all 36 documents, so its IDF is 0.01 against 1.91 for “kernel”. Words in the middle are another matter: “on” is in 15 of 36 documents and still adds about 0.9 a match. Stop-word lists still help an index's size and speed, and matter more for short fields.

03

Explain it back

Answer out loud or in writing before opening each one. These work well as a pairing exercise: one person explains, the other asks "why?" twice.

Q1Why does a rare query term count for more than a common one?
A good answer coversBM25 weights every term by its inverse document frequency, IDF = ln(1 + (N − n + 0.5)/(n + 0.5)), where n is how many of the N documents contain it. A term in one document out of 36 gets about 3.2; a term in all of them gets almost 0. Matching a rare term is strong evidence a document is about the query; matching a word every document has is no evidence at all.
Q2What does k1 control, and why does BM25 stop rewarding repetition?
A good answer coversk1 sets how fast term frequency saturates. A term's part is IDF × tf(k1+1)/(tf + k1·…), which climbs fast for the first few occurrences and then flattens toward IDF × (k1+1). k1 = 0 counts only presence; higher k1 lets repeats count longer. Typical values are 1.2 to 2.0. It's why stuffing a page with a keyword stops paying: the 20th repeat adds almost nothing.
Q3What does b do, and when would you lower it?
A good answer coversb (0 to 1, usually 0.75) scales term frequency by the document's length against the average, so a match in a short document counts more than the same match in a long one. b = 0 ignores length. Lower b when length doesn't mean a document is less focused (a field of uniformly short titles, or long documents that really are about one thing); raise it when long documents tend to mention everything.
Q4Why is BM25 so good at error codes, SKUs and names, and so bad at “my browser keeps dropping the connection”?
A good answer coversIt matches exact tokens and gives a rare token a huge weight, so a code that appears in one document ranks it first. But a query that describes the problem in other words shares no tokens with the right document and scores it near zero. Stemming, synonym lists and query expansion narrow the gap a little; semantic (embedding) search closes it, and hybrid search combines both.
Q5Do you need a stop-word list with BM25? What else in the text pipeline changes the scores?
A good answer coversNot for ranking: IDF already makes words like “the” nearly weightless, though mid-frequency words (“on”, “to”) still add a little. Stop-word lists mostly save index space. What matters more is tokenisation and normalisation: whether ERR_CONNECTION_RESET stays one token or splits into three, lowercasing, accents, and stemming (“printers” vs “printer”). Index and query must be processed the same way.
Q6Your search engine says one result scored 12.4 and another query's best scored 3.1. Is the first one a better match?
A good answer coversYou can't tell. BM25 scores depend on the query's terms, their IDFs and the corpus, so they are only comparable within one query on one index. That's why systems that merge BM25 with another ranker (for example vector search) usually combine ranks, not raw scores: Reciprocal Rank Fusion (lesson 37). Elasticsearch, OpenSearch and Lucene use BM25 with k1 = 1.2 and b = 0.75 as their default similarity.
